# Purrrfolio — спецификация реализации (command-only MVP)

Документ основан на концепт-артe [`docs/source/game-concept.png`](source/game-concept.png) и адаптирован под **Telegram-бот без Mini App**.

## Продуктовая идея

**Purrrfolio / КотоКоллекция** — уютная коллекционная игра про кавайных котиков. Игрок собирает карточки, открывает наборы за внутриигровую валюту «рыбки», завершает тематические коллекции и обменивает дубликаты.

Целевая сессия: 1–3 минуты. Весь UX — команды, reply-клавиатура и inline-кнопки Telegram.

## Что оставляем из концепта

| Механика | Реализация в боте |
| --- | --- |
| Редкость карточек (5 уровней) | Эмодзи + веса в `CardRarity`, отображение в `/collection` и при открытии набора |
| Тематические коллекции | `/themes`, бонус рыбок за полный сет |
| Открытие наборов | `/pack`, 3 карточки за 50 🐟 |
| Задания | `/daily` + простые квесты (открыть N наборов, завершить тему) |
| Обмен | `/trade @friend card_id` — P2P обмен дубликатами |
| Биржа | `/market list/browse/buy` — продажа дубликатов за рыбки |
| События | План: сезонные карточки `SPECIAL` через `/event` (фаза 2) |

## Что сознательно урезаем

| Концепт | MVP-решение |
| --- | --- |
| Mini App UI, домик, декор | Нет. Домик заменён текстовым `/profile` и прогрессом по темам |
| Анимация открытия 3D-набора | Серия сообщений: «Открываю…» → 3 карточки с картинкой + подпись |
| Визуальная сетка коллекции | Пагинированный текст + отправка PNG карточки по запросу |
| Социальный feed | Только прямые обмены и биржа, без ленты активности |
| Уровни XP / прогресс-бар | Отложено; в MVP достаточно рыбок и % коллекции |

## Команды бота

```
/start          — регистрация, welcome, reply-меню
/collection     — список карточек, количество дубликатов, кнопка «Смотреть карточки» (фото-галерея)
/pack           — открыть набор (проверка баланса, списание, выдача)
/themes         — прогресс по темам, кнопка «Забрать бонус», просмотр карточек темы
/daily          — ежедневные рыбки (1 раз в сутки по UTC)
/profile        — баланс, уникальные карточки, завершённые темы
/trade @user card_id [wanted_card_id] — предложение обмена 1:1
/market list card_id price — выставить дубликат (мин. 2 копии)
/market browse [page]     — лоты биржи
/market buy listing_id    — купить лот
/language       — сменить язык интерфейса (inline-кнопки EN/RU)
/help           — справка
```

Reply-клавиатура дублирует основные разделы: Коллекция, Набор, Темы, Обмен, Биржа, Профиль, Язык.

Команды также регистрируются в левом меню Telegram через `setMyCommands` при старте приложения: английские описания для всех (`scope type=default`), русские — для чатов с `language_code=ru` (`scope all_private_chats`).

## Локализация

- Язык по умолчанию — английский. Новый игрок получает русский только если его `language_code` в Telegram начинается с `ru`.
- Выбор хранится в `players.locale` и меняется командой `/language` (inline-клавиатура `lang:en` / `lang:ru`).
- Весь текст игроку берётся из `i18n/Messages.kt`; кнопки reply-меню локализованы и сопоставляются по нажатию независимо от регистра и пробелов.

## Потоки

### Регистрация

1. `/start` → создать `players` row по `telegram_id`.
2. Выдать стартовые 100 🐟.
3. Показать welcome + reply-меню.

### Открытие набора

1. Проверить баланс ≥ 50 🐟.
2. Списать рыбки, записать `pack_openings`.
3. Сгенерировать 3 карточки по весам редкости.
4. Upsert `player_cards.quantity`.
5. Отправить 3 сообщения с PNG (`/static/assets/cards/{id}.png`) и подписью редкости.
6. Если карточка новая — пометка ✨ NEW.

### Просмотр карточек (фото-галерея)

1. `/collection`: текстовый список + inline «🖼 Смотреть карточки» (`gal:col:0`) — галерея по уникальным карточкам игрока.
2. `/themes`: прогресс по темам + inline-кнопка на каждую тему (`gal:theme:{id}:0`) — галерея по всем карточкам темы (собранные и отсутствующие).
3. В галерее показывается PNG карточки, подпись: редкость, название, тема, количество «×N» или «ещё не собрана», счётчик «N / total».
4. Навигация — inline ◀️ / ▶️ (`gal:col:{idx}` / `gal:theme:{id}:{idx}`). Фото меняется на месте через `editMessageMedia` c `file_id` целевой карточки (file_id кэшируется с первого показа карточки); пока карточка не показывалась — отправляется новое фото с удалением предыдущего (`deleteMessage`). Пер-чат состояние message_id + index хранится в памяти; после рестарта — новое сообщение.
5. «🔙 Назад» (`gal:back`) возвращает к текстовому списку коллекции/тем.

### Завершение темы

1. `/themes` считает уникальные карточки игрока по каждой теме.
2. При `owned == total` и отсутствии claim — inline «Забрать бонус».
3. Транзакция: insert `theme_completion_claims`, credit fish.

### P2P обмен

1. Продавец имеет ≥2 копии `offered_card_id`.
2. `/trade @buyer sleepy` создаёт `trade_offers` со статусом `OPEN`, TTL 24ч.
3. Покупатель получает inline «Принять / Отклонить».
4. При принятии — атомарный swap quantity у обеих сторон (или transfer + optional requested card).

### Биржа

1. `/market list sleepy 40` — списать 1 дубликат (quantity−1), создать `market_listings`.
2. `/market browse` — paginated список ACTIVE лотов.
3. `/market buy {uuid}` — списать price у покупателя, начислить price−fee продавцу, transfer card.

## Модель данных

См. [`V1__initial_schema.sql`](../src/main/resources/db/migration/V1__initial_schema.sql) и [`V2__default_locale_en.sql`](../src/main/resources/db/migration/V2__default_locale_en.sql) (дефолт `players.locale` — `'en'`):

- `players` — профиль и баланс рыбок
- `player_cards` — инвентарь (card_id → quantity)
- `theme_completion_claims` — одноразовые бонусы
- `pack_openings` — аудит открытий
- `trade_offers` — P2P обмены
- `market_listings` — биржа
- `processed_telegram_updates` — идемпотентность webhook

## Фазы разработки

### Фаза 0 (текущий scaffold)

- Структура репозитория, документация, каталог, миграции, demo-обработчик команд.

### Фаза 1 (играбельный MVP)

- JDBC persistence, регистрация, `/pack`, `/collection`, `/themes`, `/daily`.
- Отправка PNG карточек через Telegram `sendPhoto`.

### Фаза 2 (социалка)

- `/trade`, `/market`, уведомления, anti-fraud (rate limits, min price).

### Фаза 3 (retention)

- Сезонные `SPECIAL` карточки, `/event`, реферальные награды, квесты.

## Нефункциональные требования

- Kotlin 17 + Spring Boot 3, PostgreSQL, Flyway.
- Webhook с `X-Telegram-Bot-Api-Secret-Token`.
- Идемпотентность по `update_id`.
- Prometheus metrics на `:9090/actuator/prometheus`.
- Docker Compose для локального PostgreSQL.
