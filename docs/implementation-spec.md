# Purrrfolio — спецификация реализации (command-only MVP)

Документ основан на спецификации [`docs/source/cat_card_bot_game_design_v1_3.pdf`](source/cat_card_bot_game_design_v1_3.pdf) и адаптирован под **Telegram-бот без Mini App**.

## Продуктовая идея

**Purrrfolio / КотоКоллекция** — уютная коллекционная игра про кавайных котиков. Игрок собирает карточки, открывает наборы, завершает тематические коллекции и обменивает дубликаты через Random Trade и биржу.

**БЕЗ внутренней валюты**. Только Telegram Stars для покупки паков.

Целевая сессия: 1–3 минуты. Весь UX — команды, reply-клавиатура и inline-кнопки Telegram.

## Ключевые требования из PDF

- Минимум 1000 уникальных карточек в 10 коллекциях
- Каждая карточка — отдельный 1024×1536 PNG (не вырезка из сетки)
- 6 уровней редкости: Common → Uncommon → Rare → Epic → Mythic → Legendary
- Special — отдельный тег/статус (может сочетаться с любой редкостью)
- 3 стартовых пака по 3 карточки + 1 бесплатная карточка каждые 3 часа (первая — сразу)
- Random Trade механика через общий пул
- Биржа с предложениями своих выставленных карточек
- Telegram Stars для покупки паков (1 пак = 5 Stars, 3 пака = 12 Stars, 5 паков = 16 Stars, 10 паков = 25 Stars)

## Система редкостей

| Редкость | Цвет/эффект | Стартовый вес | Эмодзи |
| --- | --- | --- | --- |
| Common | кремовый / нейтральный | ≈ 48% | ⚪ |
| Uncommon | зеленый | ≈ 25% | 🟢 |
| Rare | голубой | ≈ 15% | 🔵 |
| Epic | фиолетовый | ≈ 7% | 🟣 |
| Mythic | малиновый / переливчатый | ≈ 3% | 🔴 |
| Legendary | золотой / особое сияние | ≈ 2% | 🟠 |

Каждая коллекция содержит ровно одну карточку Legendary.

**Special** — НЕ является редкостью. Это отдельный тег/статус для event, limited, promo, achievement, gift, collaboration карточек. Может сочетаться с любой базовой редкостью.

Первая special-коллекция — `calendar-cycle` («Месяцы и сезоны»): 12 месяцев и
4 времени года. У всех её карточек `special=true`, `event=calendar-cycle`, но
`limited=false`. Единый визуальный маркер — голографический медальон в правом
верхнем углу (страница календаря внутри восьмиконечной звезды) и тонкий
радужный foil-кант. Цвет основной рамки по-прежнему определяется редкостью.
Карточка месяца выпадает только в соответствующем календарном месяце, карточка
времени года — в один из трёх месяцев этого времени года. Сначала выбирается
обычная редкость по общим весам, затем карточка среди доступных карточек этой
редкости; тег Special не меняет шанс выпадения. Часовой пояс берётся из
`purrrfolio.game-timezone`.

Вторая special-коллекция — `friendship` («Друзья»), 12 карточек о совместных
занятиях без спортивных сюжетов. У всех карточек `special=true`,
`event=group-friendship`, `groupChatOnly=true`. Они входят в пул только если
игрок запросил набор или бесплатную карточку из Telegram-чата типа `group` или
`supergroup`. В личном чате они недоступны. Сначала, как и для остальных карт,
выбирается редкость по общей шкале 48/25/15/7/3/2, затем карточка внутри
доступного пула этой редкости; Special и групповой фильтр не дают отдельного
повышенного или пониженного веса.

## Стартовая механика

1. Новый игрок автоматически регистрируется при первом поддерживаемом сообщении; RU выбирается по Telegram `language_code`, иначе используется EN
2. Создание игрока и начисление 3 стартовых паков по 3 карточки выполняются одной транзакцией
3. После первого `/start` бот отправляет короткое приветствие и отдельное сообщение с крупной inline-кнопкой открытия стартового набора
4. Первая бесплатная карточка доступна сразу, следующие — по одной каждые 3 часа от последнего клейма (`users.last_free_card_at`)
5. Бесплатные паки не накапливаются при наличии неоткрытых паков другого происхождения

## Награда за завершение коллекции

- За полную тематическую коллекцию игрок автоматически получает 1 бесплатный пак.
- Награда идемпотентна для конкретного состава коллекции: повторные команды и повторная доставка Telegram update не начисляют пак второй раз.
- Версия коллекции определяется полным набором её card_id. Если в коллекцию добавлены новые карты, версия меняется; после сбора всех карт расширенной версии игрок снова получает 1 пак.
- Уже полная коллекция проверяется при получении карточек и при открытии `/collection`, поэтому существующие игроки также получают положенную награду.
- Начисление claim и положительной записи `pack_ledger` с `source=collection_completion` выполняется одной транзакцией.

## Telegram Stars pricing

| Покупка | Цена в Stars |
| --- | --- |
| 1 пак | 5 |
| 3 пака | 12 |
| 5 паков | 16 |
| 10 паков | 25 |

После оплаты паки добавляются в доступный запас, не открываются автоматически. Игрок получает кнопку «Открыть набор / Open Pack».

## Ежедневный розыгрыш паков в группах

- Запускается автоматически после любой отработанной команды из группового чата или супергруппы; отдельной команды нет.
- Условия: в чате 10+ участников (по `getChatMemberCount`) и с прошлого розыгрыша в этом чате прошло 24+ часов. Иначе бот молчит.
- Тиры: 1 пак за каждые 10 участников, максимум 10 паков (100+ участников). Если известных боту игроков меньше, чем паков по тиру, разыгрывается меньше — по числу игроков.
- Пул победителей — зарегистрированные игроки, которых бот видел в этом чате (`group_chat_members` пополняется из каждого обработанного группового сообщения; перечислить всех участников чата Bot API не позволяет).
- Каждый победитель в момент начисления проверяется через `getChatMember`: боты и вышедшие/забаненные исключаются. Победители уникальны в пределах одного розыгрыша, каждому по 1 паку (`pack_ledger`, `source=raffle`).
- Розыгрыш, победители и число участников фиксируются в `group_raffles` / `group_raffle_winners`; одновременные триггеры сериализуются advisory lock'ом чата с перепроверкой кулдауна внутри транзакции.
- Результат отправляется в тот же чат с тегами победителей `[Имя](tg://user?id=...)`; язык сообщения — язык запустившего игрока.

## Random Trade

- Лишний экземпляр уходит в общий пул
- Если есть карточка другого игрока с другим card_id — происходит обмен
- Одинаковые карточки друг на друга никогда не меняются
- Заявка ждет в пуле до нахождения пары
- Результат обмена отправляется только двум владельцам участвующих карточек

## Биржа

- Выставлять можно только дубли
- Игрок может смотреть свои листинги и возвращать карточки в коллекцию
- Просмотр чужих карточек по коллекциям/редкостям
- Предложение одной из своих выставленных карточек в обмен на чужой листинг
- Владелец принимает или отклоняет предложение
- При принятии обе активные карточки блокируются и проверяются в escrow; обмен атомарен
- Уведомления о результате получают только владельцы двух участвующих карточек

## Команды бота

```
/start          — регистрация (авто, язык EN по умолчанию), 3 стартовых пака
/collection     — список коллекций, пагинация по 10, галерея карточек
/pack           — открыть доступный пакет (стартовый, купленный или скрафченный)
/freecard        — сразу забрать бесплатную карточку, если она готова (далее каждые 3 часа)
/craft           — крафтер: плавить дубликаты в очки, 15 очков = 1 пак
/trade          — Random Trade (дубли в пул, обмен)
/market         — биржа (свои листинги, просмотр чужих, предложения)
/language       — сменить язык интерфейса (inline-кнопки EN/RU)
/help           — справка
/paysupport     — поддержка платежей и возвратов Stars
```

Reply-клавиатура: Коллекция, Набор, Обмен, Биржа, Купить наборы, Карточка, Крафт, Язык.

В `/help` есть inline-кнопки для набора, бесплатной карточки, крафта и биржи.
Те же действия распознаются по простым словам без `/`: `pack`, `card pack`,
`craft`, `market`, `marketplace`; `набор`, `пак`, `крафт`, `биржа`.
Бесплатную карточку также запрашивают словами `card`, `free card`, `cat`,
`kitty`, `kitten`; `карточка`, `бесплатная карточка`, `котик`, `кот`, `котейка`,
`кошка`, `котёнок`/`котенок`. Регистр, пробелы по краям и конечная пунктуация
игнорируются.

Произвольный текст и неподдерживаемые slash-команды бот молча игнорирует, не
отправляя подсказку `/help`. В личных и групповых чатах он отвечает на
поддерживаемые команды, элементы управления и перечисленные текстовые аналоги.

## Локализация

- Новичкам сразу ставится English; русский выбирается через `/language`
- Язык можно сменить командой `/language` в любой момент
- Все сообщения, кнопки, описания команд, платежные тексты имеют RU/EN-версии
- Названия на изображениях остаются английскими
- Тексты должны звучать как игра: котейки, пушистики, лапки

## Модель данных

### Таблицы PostgreSQL

- `users` — telegram_user_id, language, last_free_card_at, craft_points, available_packs
- `collections` — id, code, localized_name, sort_order, active
- `cards` — id, collection_id, english_title, rarity_id, image_ref, sort_order, active, special/limited/event metadata
- `rarities` — id, code, probability/weight, frame_theme, sort_order
- `user_cards` — user_id, card_id, quantity
- `pack_ledger` — starter/stars начисления и opened-списания
- `collection_completion_rewards` — идемпотентные награды по user, collection и версии состава
- `random_trade_pool` — user_id, card_id, status, matched_trade_id
- `market_listings` — seller_id, card_id, status
- `trade_offers` — target_listing_id, offered_listing_id, status
- `payments` — Telegram payment IDs, Stars, packs granted, status
- `payment_support_requests` — выбранный платёж, причина, статус решения и сообщение администратора
- `processed_telegram_updates` — идемпотентность webhook
- `pack_opening_receipts` — результат открытия по Telegram `update_id`, чтобы ретрай не списывал второй набор
- `referral_rewards` — один идемпотентный реферальный claim на нового игрока с признаком начисления награды автору ссылки
- `telegram_card_files` — сохранённый Telegram `file_id` изображения каждой карточки для inline-публикации

## Потоки

### Регистрация

1. Первое поддерживаемое сообщение (команда, документированный алиас или кнопка, в личке или группе) автоматически регистрирует игрока; RU выбирается по Telegram `language_code`, иначе используется EN. Payload deep-ссылки (`?start=источник`) сохраняется в `users.registration_source`
2. В одной транзакции создать `users` row по `telegram_user_id` и добавить 3 стартовых пака в `pack_ledger` (`source=starter`); `ON CONFLICT` закрывает гонку двух первых сообщений без повторного начисления
3. Если payload имеет вид `ref_<существующий users.id>`, в той же транзакции записать уникальный claim и начислить новичку ещё 5 паков; итог новичка — 8 паков. Рефереру начислить 5 паков только за первые 10 регистраций по его ссылкам в текущем календарном месяце игрового часового пояса. Начиная с 11-й регистрации новичок по-прежнему получает 8 паков, а реферер награду не получает
4. Команда обрабатывается сразу, без экрана выбора языка; язык меняется позже через `/language`

### Открытие набора

1. Заблокировать строку игрока `FOR UPDATE` и внутри транзакции повторно проверить `available_packs > 0`
2. Списать 1 пак из `pack_ledger`
3. Сгенерировать 3 карточки по весам редкости
   - Calendar Cats фильтруются по текущему месяцу игрового часового пояса
   - Friends допускаются только для запроса из `group`/`supergroup`
4. В той же транзакции выполнить upsert `user_cards.quantity`, начислить награды за завершённые коллекции и сохранить `pack_opening_receipts` для текущего `update_id`
5. Отправить 3 сообщения с PNG, подписью редкости и кнопкой «Поделиться карточкой»; при ошибке фото использовать текстовый fallback
6. Если карточка новая — пометка ✨ NEW
7. После карточек показать итог: число новых карт и прогресс затронутых коллекций
8. При повторной доставке того же Telegram update восстановить карточки из квитанции без нового списания и начисления

### Поделиться карточкой

- Кнопка с `switch_inline_query` открывает стандартный Telegram chooser и доступна в reveal-сообщениях и галерее коллекции. После выбора чата пользователь нажимает на результат — в inline mode именно он отправляет карточку, отдельной кнопки отправки Telegram не показывает. Короткий заголовок результата объясняет этот шаг. Inline mode должен быть включён для бота в BotFather.
- Бот получает `inline_query`, проверяет совпадение Telegram-автора с внутренним владельцем и наличие карточки, затем отвечает `InlineQueryResultArticle` с одной текстовой строкой и миниатюрой карточки без дополнительного описания. После выбора статья отправляет `InputRichMessageContent` с изображением по сохранённому Telegram `file_id`.
- В публикации отображаются фотография, название и редкость карточки, именованная HTML-ссылка для старта и отдельная URL-кнопка. Публичный URL изображения и сырой URL реферальной ссылки в текст не вставляются.
- В query и deep link используется внутренний `users.id`, а не Telegram ID; `card_id` служит только для выбора принадлежащей игроку карточки.
- Новый игрок сохраняет `ref_<id>` в `users.registration_source` и получает обычные 3 стартовых пака плюс 5 реферальных — всего 8. Пригласивший получает 5 паков за первые 10 новых игроков в календарном месяце; последующие новички всё равно получают 8 паков.
- Награда выдаётся только при первом создании профиля по валидной ссылке на существующего игрока. Повторный `/start`, существующий аккаунт, несуществующий реферер и самореферал ничего не начисляют.
- Claim в `referral_rewards`, запись `referral_joiner` и, если лимит не исчерпан, запись `referral_referrer` создаются в той же транзакции, что пользователь и его стартовые паки. `referred_user_id` уникален, поэтому повторное начисление невозможно; блокировка строки реферера не позволяет конкурентным регистрациям превысить месячный лимит.
- После успешного начисления новичок получает локализованное уведомление и кнопку открытия набора с актуальным балансом. Реферер получает уведомление только при фактическом начислении своих 5 паков.

### Бесплатная карточка

1. Первая доступна сразу после регистрации (`last_free_card_at IS NULL`)
2. Команда `/freecard` или кнопка «🎁 Карточка» сразу выдаёт карточку, если она готова; дополнительной inline-кнопки нет
3. Ролл 1 карточки по весам редкости, upsert `user_cards.quantity`
   - при запросе из `group`/`supergroup` в пул добавляется special-коллекция Friends
4. Атомарно обновить `last_free_card_at`; следующая — через 3 часа
5. Если карточка ещё не готова, показать оставшееся время в часах и минутах
6. Кнопка открытия набора под выпавшей карточкой показывается только при наличии доступного набора

### Крафтер паков

1. `/craft` показывает баланс очков (`craft_points` / 15) и дубликаты с ценой
2. Один тап сжигает 1 копию дубликата (одна всегда остаётся) и начисляет очки: Common = 1, Uncommon = 2, Rare = 3, Epic = 4, Legendary/Mythic = 5
3. Каждые 15 очков: счётчик сбрасывается, в `pack_ledger` добавляется 1 пак (source=craft)
4. Переполнение переносится: 14 + 2 = 16 → 1 пак + 1 очко в зачёт следующего
5. Скрафченные паки открываются через `/pack`

### Возврат карточек

- Случайный обмен: ожидающие заявки в `/trade` возвращаются кнопкой «↩️ Вернуть» (статус CANCELLED, копия назад в коллекцию)
- Биржа: свои лоты возвращаются кнопкой «↩️ Вернуть» в `/market` (статус CANCELLED, копия назад в коллекцию)

### Покупка паков за Stars

1. Интеграция с Telegram Payments API
2. Invoice payload подписан HMAC и привязан к Telegram ID покупателя; на pre-checkout и successful_payment проверяются подпись, покупатель, `XTR` и точная сумма
3. После успешной оплаты одной транзакцией записать `payments` и добавить паки в `pack_ledger` (`source=stars`); повторная доставка того же charge ID не начисляет паки повторно
4. Показать подтверждение + кнопку «Открыть набор»

### Поддержка платежей и возвраты

1. `/paysupport` показывает только завершённые покупки игрока без уже созданной заявки на поддержку
2. `/paysupport <ID> <причина>` создаёт сохранённую заявку и отправляет её в приватный `ADMIN_TG_ID`
3. Администратор использует `/refund <ID>`, `/reject <ID> <причина>` или `/ask <ID> <вопрос>`; отвечать на уточнение можно через `/answer <ID> <ответ>`
4. Только одновременно совпадающие `chat.id` и `from.id` из `ADMIN_TG_ID` имеют право выполнять административные команды
5. После подтверждения Telegram возврат и локальная компенсация идемпотентны: платёж получает `REFUNDED`, заявка закрывается, а в `pack_ledger` появляется одна отрицательная запись `source=refund`
6. Если купленные наборы уже открыты, компенсация может сделать баланс наборов отрицательным; будущие начисления сначала погашают этот баланс

### Random Trade

1. Игрок выбирает дубликат для обмена
2. Карточка уходит в `random_trade_pool` со статусом WAITING
3. Система ищет пару: другой игрок с WAITING карточкой другого card_id
4. При нахождении — атомарный обмен, статус MATCHED
5. Уведомление обоим игрокам
6. Несостоявшуюся заявку можно вернуть кнопкой «↩️ Вернуть» (статус CANCELLED)
7. `/trade` всегда показывает WAITING-заявки игрока с кнопками возврата, даже если свободных дубликатов больше нет; сообщение об отсутствии дубликатов выводится только при пустых дублях и пустом пуле

### Биржа

1. `/market list card_id` — создать `market_listings` (quantity−1 у игрока)
2. `/market browse` — просмотр активных листингов по коллекциям/редкостям
3. `/market offer listing_id my_listing_id` — предложить обмен
4. Создать `trade_offers` со статусом PENDING
5. Владелец принимает/отклоняет через inline-кнопки
6. При принятии — блокировка и проверка обоих активных лотов, затем атомарный обмен карточек
7. Итоговые уведомления отправляются только двум владельцам карточек

## Геометрия карточек

- Финальный размер: 1024 × 1536 px (2:3)
- Формат: PNG, RGB/sRGB
- Safe area: 24 px от внешнего края
- Внешняя рамка: 24-32 px, скругление 55-65 px
- Основная арт-зона: примерно x=45-979; y=35-1250
- Nameplate: примерно y=1240-1480; высота около 240 px
- Paw badge: верхний левый угол, область около 175-190 px

## Definition of Done

- Не менее 1000 уникальных карточек минимум в 10 коллекциях
- Каждая карточка — самостоятельный 1024×1536 PNG, не вырезка из сетки
- Единый master-template рамки, плашки, badge и типографики
- Английское название занимает 1-2 строки, корректно переносится и автоматически масштабируется
- Редкость соответствует шкале Common → Uncommon → Rare → Epic → Mythic → Legendary
- Special хранится отдельно от редкости и может сочетаться с любым rarity
- Внутренний арт уникален и соответствует качеству эталона Sleepy
- Нет случайного текста, артефактов, пикселизации и обрезанных элементов
- collection_id и sort_order заполнены
- Файл прошел автоматическую проверку формата/разрешения и визуальный QA

## Нефункциональные требования

- Kotlin 17 + Spring Boot 3, PostgreSQL, Flyway
- Webhook с `X-Telegram-Bot-Api-Secret-Token`
- Lifecycle идемпотентности по `update_id`: `PROCESSING` во время обработчика, `PROCESSED` после успеха, освобождение claim при ошибке; устаревший claim можно перехватить через 5 минут
- Для открытия набора отдельная квитанция по `update_id` защищает баланс и инвентарь от повторного применения при ретрае отправки
- Prometheus metrics на `:9090/actuator/prometheus`
- Docker Compose для локального PostgreSQL
- Telegram Payments API для Stars
